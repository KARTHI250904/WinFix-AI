## 1. Executive Summary & Exact Root Cause

### The Problem
When real microphone recordings or WAV files (e.g. `2026-10-02T15-38_audio.wav`) were transcribed in the UI, WinFix AI received the audio bytes but returned an empty transcript, displaying:
> *"Voice Processing: Audio was received, but no spoken words were detected in the recording."*

### The Exact Root Cause
1. **PyAV 19.0.0 API Incompatibility:** The installed PyAV library (`av 19.0.0`) removed/deprecated the keyword argument `metadata_errors` from `av.open()`.
2. **Upstream Helper Failure:** When `faster_whisper.audio.decode_audio(io.BytesIO(audio_bytes))` was invoked, it failed internally with:
   ```text
   TypeError: open() got an unexpected keyword argument 'metadata_errors'
   ```
3. **Silent Exception Fallback Cascade:** The exception handler fell back to passing `io.BytesIO(audio_bytes)` directly into `model.transcribe(BytesIO)`. Internally, CTranslate2/faster-whisper re-invoked `decode_audio(BytesIO)` which failed with the exact same `TypeError`, producing **0 segments** from the generator (`full_text = ""`).
4. **Empty Transcript Trigger:** The resulting empty text triggered `VoiceStatus.TRANSCRIPT_EMPTY`, causing the UI to report that no intelligible speech was recognized despite the audio containing high-amplitude speech.

## 2. Technical Fix Architecture

### Direct In-Memory PCM Decoding (`decode_audio_to_numpy`)
We replaced the dependency on `faster_whisper.audio.decode_audio` with a native PyAV resampler in [`ai/voice_transcriber.py`](file:///c:/Users/karth/OneDrive/Desktop/WinFix-AI/ai/voice_transcriber.py):
- Opens the audio container using `av.open(io.BytesIO(audio_bytes), mode="r")` (compatible with PyAV 19.0+ and all earlier versions).
- Direct frame extraction via `av.AudioResampler(format="fltp", layout="mono", rate=16000)`.
- Fallback to Python standard library `wave` module for uncompressed PCM WAV.
- Passes the pre-decoded 1D `numpy.ndarray` (`dtype=np.float32`, normalized range `[-1.0, 1.0]`) directly into `model.transcribe(audio_arr, beam_size=5)`.

## 3. Decisive Evidence: Speech Presence vs. Waveform Energy

> [!IMPORTANT]
> **Non-zero audio samples / RMS power do NOT prove that human speech is present.**
> 
> Acoustic energy (non-zero samples, high peak amplitude, RMS > 0) can be generated by microphone hum, ambient air conditioning, fan noise, keyboard clicks, or electrical static. 
>
> Therefore, WinFix AI maintains a strict boundary:
> 1. **Signal Level (PCM Decoding)**: Non-zero samples and RMS verify only that the audio container was successfully decoded into uncorrupted floating-point PCM.
> 2. **Decisive Evidence (Whisper)**: Human speech is proven **ONLY** when `faster-whisper` decodes the waveform into one or more segments containing intelligible words (`len(segments) > 0` and non-empty `segment.text`).
> 3. **Silence / Noise Gate**: If Whisper yields zero segments or segments without recognizable words, the system truthfully reports `VoiceStatus.TRANSCRIPT_EMPTY`, regardless of the recorded waveform's volume or amplitude.
